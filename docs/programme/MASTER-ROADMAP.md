# Master Roadmap

## Programme structure
The programme begins with Kubernetes operations and later expands into other DevOps, Cloud, SRE and Platform Engineering domains. AI agents are the product; Kubernetes is the first domain.

## Portfolio register
The complete candidate portfolio and scoring record is maintained in [PROJECT-SCORECARD.md](PROJECT-SCORECARD.md). It is programme planning material, not a release announcement. Each project requires explicit individual approval before implementation.

## Delivery model
Each agent is a standalone build with its own scope, interfaces, acceptance criteria, AWS cost estimate, test plan, security review, deployment procedure, teardown procedure and handoff documentation.

Reuse common foundations only when a real need is demonstrated. Avoid premature platform-building and empty project scaffolds.

## Release gates
1. Problem and alternatives research complete.
2. Project-level approval recorded.
3. Architecture, threat boundaries and cost estimate reviewed.
4. Implementation and automated tests complete.
5. AWS deployment and required integration tests complete.
6. Evaluation evidence, operational docs and limitations published.
7. Billable resources terminated and teardown verified, unless persistence has explicit approval.

## Future domains
After the initial Kubernetes portfolio, new domain proposals will be researched and added through documented roadmap updates. There is no fixed end date; quality and independent usefulness take precedence over a calendar deadline.
